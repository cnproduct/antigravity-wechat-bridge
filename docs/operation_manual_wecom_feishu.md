## 三、 第一步：商业准入与授权激活

系统严格执行 **“先核验有效商业卡密，后开放上架”** 的准入规则。每个微信/飞书对话窗口独立绑定一个专属会话识别码（Conversation ID），未激活状态下无法执行上架或绑定操作。

### 1. 激活操作指令
用户在微信或飞书对话框直接发送管理员签发的卡密：

```text
激活授权 LIC-RSA-xxxxxxxxxxxxxxxxxxxxxxxx
```

> **系统执行行为**：
> 1. 助手调用底层 `activate` 接口，核验卡密有效天数与当前会话数字签名。
> 2. 激活成功后，助手原样回显商业授权到期时间（UTC），并在聊天中对卡密明文进行自动脱敏。
> 3. 立即提示用户：“商业授权已就绪，请绑定您的 Wildberries 店铺”。

### 2. 状态速查与移动端身份识别机制
用户可随时在聊天中输入以下指令查看当前窗口与店铺状态：
- `查询状态` 或 `status`：查看当前绑定的 WB 店铺、仓库编号、连通性及卡密剩余有效天数。
- `身份信息` 或 `identity`：查看当前账号的身份标识、隔离会话 ID 及绑定详情。

#### 💡 移动端（微信/飞书）与传统 Windows 电脑端的身份识别差异
- **传统 Windows 电脑端**：由于本地没有平台账号，必须通过主板/网卡生成硬件**机器码（SID）**与 PowerShell 窗口**会话码（CID）**，需要用户手动复制长字符串，门槛较高。
- **微信 / 飞书手机端（体验质的飞跃）**：**手机端用户完全不需要关心什么是底层硬件 SID，也无需手动查找复杂的机器码！**
  - **微信端**：腾讯服务器协议原生自带不可伪造的 `WeChat UserID`（或客户微信号），系统自动将其 1:1 映射为持久化的专属会话 ID（CID）。
  - **飞书端**：飞书长连接网关自带身份签名，机器人秒级解析消息发送者的实名姓名与企业全局唯一 `Open ID`。
  - **换机无忧**：只要微信号或飞书号不变，无论是更换 iPhone、安卓还是电脑登录，历史店铺绑定与未到期授权自动无缝沿用。

#### 📱 手机端输入“身份信息”回显示例：

## 四、 第二步：Wildberries 店铺绑定 SOP

绑定是将当前对话窗口与商家的 Wildberries 卖家后台建立互信连接，每个会话窗口实行 **1:1 独立互斥锁定**，严防不同客户或员工串店。

### 1. 商家需提前准备的材料
1. **WB API 令牌 (API Token)**：
   - 登录 Wildberries 卖家后台（Seller Portal）-> 设置 -> 访问令牌。
   - 生成标准供应商令牌，勾选：`Content (商品内容)`、`Prices & Discounts (价格折扣)`、`Marketplace (仓库库存)`、`Статистика (统计数据)`。
   - 官方默认有效期通常为 180 天。
2. **WB FBS 仓库 ID (Warehouse ID)**：
   - 在 WB 卖家后台 `Маркетплейс` -> `Мои склады`（我的仓库）中查看。
   - 通常为一串数字（例如 `2200772`）。
3. **店铺自定义名称**：
   - 如“我的WB一号店”，便于标识。

### 2. 绑定对话输入格式
商家在已激活的微信或飞书对话中直接发送：

```text
绑定店铺
店铺名称：人人易WB旗舰店
仓库ID：2200772
API令牌：eyJhbGciOi...（粘贴完整令牌）
```

> **系统执行行为**：
> 1. 智能体接收到后，通过安全管道传入底层 `bind` 命令，测试 WB 官方接口网络连通性。
> 2. 核实仓库 ID 是否真实存在、API 令牌是否有权限操作该仓库。
> 3. 校验通过后，回显“店铺绑定成功！已锁定当前独立会话”。
> 4. **安全保护**：对话中绝对不会回显或泄露商家的明文 API 令牌。

## 五、 第三步：商品极速自动化上架全流程

完成绑定后，即可随时向助手下达上架指令。系统支持 **单款极速上架** 和 **批量多款上架** 两种模式。

---

### 1. 单款极速上架
商家在对话中发送单个 Ozon 商品链接或商品 SKU 编码：

```text
上架商品
SKU：1749812938
加价倍数：5
库存：5
```
*(或直接发送 Ozon 网址：`https://www.ozon.ru/product/1749812938/`)*

**智能体后台执行链路**：
1. **核实与抓取**：自动调取受控浏览器打开 Ozon 商品主页与规格参数页，核实并锁定卢布原生兑换人民币（CNY）绿标价格，提取商品标题、多属性、类目特性与高清主图。
2. **类目精准匹配**：将 Ozon 产品特征与 Wildberries 平台官方类目库进行唯一精确匹配，绝不瞎猜或兜底。
3. **官方货号生成**：自动生成标准化防重货号 `ozYYYYMMDD-<Ozon原始SKU>`（例如 `oz20261003-1749812938`）。
4. **价格与折扣运算**：按划线价倍数（默认 5 倍）计算建议零售价，并配合 WB 官方促销折扣（默认注入 50% 现货大促保护）。
5. **WB 后台写入与核验**：通过 WB Content API 提交商品资料，并即时回读 WB 审核状态与创建的真实 `nmID`。
6. **对客汇报**：在聊天窗口回复处理结果、商品货号、设定的人民币售价、库存及买家端链接状态。

### 5. Ozon 价格采集与币种核验底层机制（严禁公网汇率估算）

许多刚接触移动端上架的卖家会产生疑问：*“手机端无法操作浏览器，如果遇到币种未显示人民币或页面受阻，能否直接按 Google 搜索的卢布汇率折算成人民币套入公式？”*

答案是：**绝对不行！系统底层严格禁止任何形式的“估算汇率或猜价上架”。**

#### 🛡️ 为什么绝对不能用 Google / 银行外汇牌价折算？
1. **Ozon 官方结算汇率 ≠ 实时银行外汇中间牌价**：
   - Ozon 针对中国跨境卖家的结汇汇率、买家端的 Ozon 绿标卡折扣价，与 Google 上的公网中间汇率存在 **3% ~ 8% 的动态利差与跨境手续费溢价**。
2. **严防“爆单即巨亏”的汇损倒挂惨剧**：
   - 如果 AI 自行用 Google 汇率折算，极易把进货成本算低；再经过 WB 平台的划线价与大促活动折扣（如 50% 现货大促保护），**最终在 WB 的实际售价很可能会低于卖家在 Ozon 真实的采购扣款**！
   - 卖家看似出了很多单，实际每发一单都在巨额亏损。
3. **资金安全风控底线**：
   - 核心规则规定：**“不猜价格或汇率，未取得真实原生人民币绿标价证据，绝不上架”**。守住卖家的利润底线永远高于上架速度。

#### ⚙️ 手机端运行与容错机制（用户完全无感）
- **误区澄清**：浏览器**绝不是**在用户的手机上运行，而是在运行 Antigravity 的云端/本地服务器后台静默运行。
- **全自动核验**：智能体在后台受控浏览器中会自动打开 Ozon 币种菜单，秒级搜索并切换至 `CNY`（人民币）并保存，全自动核验绿标价格，**手机端用户无需任何浏览器操作**。
- **遇阻自动跳过（轻量容错隔离）**：
  - 在批量上架过程中，若极个别款式遭遇 Ozon 的强人机滑块验证或网络限制，智能体**绝不会卡死整个队列**。
  - 系统会**自动跳过该 SKU 并标记为“待核实”**，无缝继续抓取后续成百上千款正常商品。
  - 任务结束后在微信/飞书报告中清晰列出：“本次提交 50 款，已成功写入 48 款；其中 2 款因平台人机验证暂未提交，已安全隔离”。
  - 待电脑端管理员有空时完成单次滑块核验，直接在手机发送 `继续未处理的商品` 即可一键补齐，既高效又 100% 安全。

## 七、 高频疑难排障全景 FAQ

### Q1：提示“未检测到有效商业授权”或“自助免费试用已关闭”？
- **原因**：当前会话窗口尚未激活有效卡密。
- **解决办法**：
  1. 请联系管理员或代理商获取商业卡密（格式为 `LIC-RSA-xxxx`）。
  2. 复制卡密后，在聊天窗口直接发送：`激活授权 <您的卡密>`。
  3. 系统激活后即可继续操作。

### Q2：绑定店铺提示“仓库 ID 无效”或“Token 权限不足”？
- **原因 1（仓库错误）**：填写的不是 FBS 仓库编号。
  - **核对方式**：必须在 WB 卖家后台 `Маркетплейс` -> `Мои склады` 中找到实际存在的数字 ID（如 `2200772`），不能随意填写虚拟数字。
- **原因 2（令牌权限缺失）**：生成的 WB Token 未勾选完整权限。
  - **核对方式**：在 WB 后台重新生成 Token，务必勾选 `Content`（商品）、`Prices`（价格）、`Marketplace`（仓库）。

### Q3：抓取 Ozon 时提示核对人民币或页面被阻，手机端能否用 Google 汇率折算上架？
- **答**：**绝对不能！系统严禁任何形式的公网汇率估算猜价**。
  - **核心风控**：Ozon 平台的实时结算汇率和绿标折扣与 Google 牌价存在 3%~8% 的动态利差与跨境手续费溢价。如果 AI 自行按 Google 汇率折算，极易把进货成本算低，经 WB 官方划线倍数与大促活动折算后，**极大概率出现“实际成交售价低于采购进货扣款”的恶性亏损倒挂**。
  - **手机端无感解决**：浏览器在服务端后台自动静默切换为 CNY 并核实绿标价，用户手机端无需任何操作。
  - **遇阻跳过与补漏**：遇到偶发人机滑块拦截时，系统会自动跳过该款继续处理后续 98% 的商品，并在最终报告中列出待核验 SKU，绝不卡死任务队列，守住卖家的利润红线。

### Q4：上架后在 Wildberries 后台找不到商品，或显示待审核？
- **解释**：
  - 智能体写入成功后，WB 官方后台会有 **3~15 分钟** 的内容同步与审核索引周期。
  - 刚写入的商品可以在 WB 卖家后台的 `Товары` -> `Карточка товара`（商品卡片）中查看“审核中/Обработка”列表。
  - 平台索引完毕后会自动生成官方 `nmID` 并上线。

### Q5：不同员工或多个微信/飞书用户同时使用，会不会串店？
- **答**：**绝对不会**。
  - 系统为每一个独立的微信 UserID 或飞书 OpenID 分配独立的 `Conversation ID`。
  - 每一个 `Conversation ID` 严格分配一个互斥的物理沙盒目录（如 `tenants/feishu_ou_xxx/conv_yyy/`）。
  - 所有底层执行命令均强制传递 `--conversation-id <专属ID>`，不同用户之间的商品文件、上传目录、WB 店铺凭证在底层完全隔离互斥。

### Q6：云服务器关机或重启后，需要重新绑定店铺或买卡密吗？
- **答**：**不需要**。
  - 会话映射与授权记录持久化存储在云端与本地数据库中（`wechat_sessions.json` 及 KV）。
  - 服务器重启后，运行 `./.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000` 即可自动恢复所有历史绑定与未到期的授权状态。

### Q7：手机端没有 Windows 机器码（SID），管理员如何为手机微信/飞书用户发卡？
- **答**：**手机端免去了一切繁琐的硬件机器码查找与报错**。
  - 微信用户天然以 `WeChat UserID` 识别，飞书用户天然以企业 `Open ID` 识别。
  - 管理员在发卡后台签发卡密后，客户只需在手机微信或飞书对话中直接粘贴发送：`激活授权 LIC-RSA-xxxx`，系统自动秒级完成与当前微信号/飞书号的会话锁定，无需向管理员报送任何机器码，换手机登录也不会丢失授权。
